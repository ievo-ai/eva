## 4. Findings

### F-2026-06-15-001 — Document ANTHROPIC_DEFAULT_*_MODEL bypass in AGENTS.md security model section

**Status:** issued → https://github.com/ievo-ai/skills/issues/207  
**Effort:** low | **Scope:** single-file (AGENTS.md)

Claude Code v2.1.176 (Jun 12) made `ANTHROPIC_DEFAULT_*_MODEL` env vars reliably enforced against redirects. This creates a sixth model-downgrade bypass vector for the security-auditor agent (after the five in issues #176, #180, #195, #197, #199). AGENTS.md security model section currently only documents `CLAUDE_CODE_SUBAGENT_MODEL`. Adding a bullet for `ANTHROPIC_DEFAULT_SONNET_MODEL` with the positive-control / bypass-vector framing closes this gap.

### F-2026-06-15-002 — Reorder all 14 SKILL.md descriptions to trigger-intent framing

**Status:** issued → https://github.com/ievo-ai/skills/issues/205  
**Effort:** medium | **Scope:** multi-file (14 × SKILL.md)  
**Credit:** @DenisSergeevitch/agents-best-practices (`references/skills-and-connectors.md`, Jun 14)

All 14 iEvo `description:` fields start with implementation language ("Vulnerability assessment by...", "Structured 10-point gap-detection...") rather than trigger-intent framing ("Use this skill when..."). agentskills.io guidance and DenisSergeevitch both recommend trigger-first because agent runtimes load only the opening tokens at startup. `vuln-scan/SKILL.md` has no "Use when" clause at all. Note: distinct from #174 (separate `when_to_use:` frontmatter field) — this reorders existing `description:` content, no schema change.

### F-2026-06-15-003 — Add active-plan and overlay-reference sections to /ievo:handoff output

**Status:** issued → https://github.com/ievo-ai/skills/issues/206  
**Effort:** low | **Scope:** single-file (`handoff/SKILL.md`)  
**Credit:** @DenisSergeevitch/agents-best-practices (`references/context-memory-compaction.md`, Jun 14)

The 12-tier context model identifies Tier 5 (active plan state) and Tier 6 (scoped instructions / overlays) as critical context for session handoffs. `handoff/SKILL.md` captures neither. Two proposed additions: (1) `## Active plan state` section with 1-paragraph work-stage summary, (2) explicit `Run /ievo:overlay-status` action reference in the overlays section so the receiving session doesn't have to discover overlays by trial and error.
